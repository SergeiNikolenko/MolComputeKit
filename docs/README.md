# Documentation map

MolComputeKit has two documentation layers with different audiences:

- `docs/content/` is the reader-facing Nextra site. It teaches installation,
  API selection, examples, backend evidence, and troubleshooting.
- the uppercase Markdown files in `docs/` are engineering records for
  architecture, extraction, integration, and validation evidence.

The reader-facing pages summarize code and tests; they do not replace the Rust
API documentation generated by `cargo doc` or the versioned JSON Schemas.

## Run the Nextra site

Requirements: Node.js 20.9 or newer and npm.

```bash
cd docs
npm ci
npm run dev
```

Build the production site and Pagefind search index with:

```bash
npm run build
```

From the repository root, the equivalent commands are `npm run docs:dev` and
`npm run docs:build`.

## Dependency policy

The docs dependencies are exact pins and `package-lock.json` is committed. Keep
`nextra` and `nextra-theme-docs` on the same version, then verify production
build, search, desktop layout, and mobile navigation together when upgrading.
The tested set currently holds both Nextra packages at `4.2.17`: the published
`4.6.1` theme build rejected the required `Layout` children in this Next.js 15
stack. The current overrides retain React 19 compatibility for Mermaid and a
patched PostCSS release.

## Deployment

The current configuration builds a server-rendered Next.js site suitable for a
Node host or Vercel-style deployment. CI verifies the site but does not publish
it. A GitHub Pages deployment would need an explicit static export, repository
`basePath`, and Pagefind output under `out/_pagefind`; choose the public host
before adding that separate contract.

## Content map

| Need | Start here |
| --- | --- |
| Install a pinned release | `content/getting-started/installation.mdx` |
| Run a first calculation | `content/getting-started/quick-start.mdx` |
| Choose CPU, Metal, or helper execution | `content/concepts/backend-evidence.mdx` |
| Understand module boundaries | `content/concepts/architecture.mdx` |
| Find a Rust type or entry point | `content/reference/api-map.mdx` |
| Validate JSON and artifact contracts | `content/reference/protocol-schemas.mdx` |
| Diagnose setup and runtime errors | `content/troubleshooting.mdx` |

## Engineering records

- `ARCHITECTURE.md` — implementation layers and compatibility boundaries.
- `INTEGRATION.md` — host responsibilities and result evidence.
- `VALIDATION.md` — continuous checks and real-device evidence.
- `EXTRACTION.md` — origin and compatibility record for v0.1.0.
- `third-party/mlxmolkit-provenance.md` — file-level attribution and parity
  ledger.

When public behavior changes, update the relevant reader-facing page and the
engineering record that owns the claim in the same pull request.
